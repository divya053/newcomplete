## 1. Executive Summary

The **BOQ Intelligence Platform** automates Bill of Quantities (BOQ) generation from construction documents (DWG, DXF, PDF, DOCX) using a four-stage multi-agent AI pipeline. Two independent AI agents generate BOQs in parallel, a verifier agent cross-checks them, and the consensus result is stored with per-item verification status.

### Key Enterprise Value Propositions

| Metric | Manual Process | BOQ Intel Platform |
|--------|---------------|-------------------|
| BOQ Generation Time | 3–5 days | 5–15 minutes |
| Quantity Surveyor Hours | 40–80 hrs/project | 2–4 hrs review |
| Human Error Rate | 8–15% | <2% (multi-agent verified) |
| Cost per BOQ | $2,000–$8,000 | $2–$40 (AI cost) |
| Parallel Projects Supported | 3–5 | Unlimited |
| Discrepancy Detection | Manual | Automated (Agent 4) |

## 3. Multi-Agent Pipeline Architecture

### Agent Pipeline Flow

```mermaid
sequenceDiagram
    participant U as User
    participant API as API Server
    participant A1 as Agent 1 Extractor
    participant A2 as Agent 2 Primary BOQ
    participant A3 as Agent 3 Secondary BOQ
    participant A4 as Agent 4 Verifier
    participant DB as PostgreSQL

    U->>API: POST /generate-boq-multi {provider, model}
    API-->>U: SSE Stream opened

    API->>DB: Load project + documents
    API-->>U: event: pipeline {stage: loading}

    API->>A1: Extract structured data from documents
    API-->>U: event: agent {extractor, running}
    A1-->>API: {projectType, materials, dimensions, quantities}
    API-->>U: event: agent {extractor, complete}

    par Parallel Execution
        API->>A2: Generate BOQ (Quantity Surveyor role)
        API-->>U: event: agent {primary, running}
    and
        API->>A3: Generate BOQ (Cost Estimator role)
        API-->>U: event: agent {secondary, running}
    end

    A2-->>API: Primary BOQ JSON (15-25 items)
    A3-->>API: Secondary BOQ JSON (15-25 items)
    API-->>U: event: agent {primary, complete}
    API-->>U: event: agent {secondary, complete}

    API->>A4: Compare + verify both BOQs
    API-->>U: event: agent {verifier, running}
    A4-->>API: Consensus BOQ with verificationStatus per item
    API-->>U: event: agent {verifier, complete, summary}

    API->>DB: Save verified items (with status, notes, method)
    loop Each verified item
        API-->>U: event: item {boqItem}
    end

    API-->>U: event: done {summary}
```

### Agent Role Definitions

```mermaid
graph TD
    subgraph A1["Agent 1 — Document Extractor"]
        E1["Parse uploaded files\n(PDF, DWG, DOCX, TXT)"]
        E2["Extract: rooms, areas, floors\nmaterials, dimensions, equipment"]
        E3["Output: Structured JSON\nextraction summary"]
        E1 --> E2 --> E3
    end

    subgraph A2["Agent 2 — Primary BOQ\n(Senior Quantity Surveyor)"]
        P1["Receives extraction summary"]
        P2["Conservative, meticulous\ntake-off approach"]
        P3["15-25 line items\nwith confidence scores"]
        P1 --> P2 --> P3
    end

    subgraph A3["Agent 3 — Secondary BOQ\n(Independent Cost Estimator)"]
        S1["Receives same extraction summary"]
        S2["Commercial accuracy focus\ncompleteness driven"]
        S3["Independent 15-25 items\nno knowledge of Agent 2"]
        S1 --> S2 --> S3
    end

    subgraph A4["Agent 4 — Verifier & Consensus"]
        V1["Receives both BOQs"]
        V2["Match similar items\nby description + category"]
        V3{"Quantity difference\n< 15%?"}
        V4["Status: AGREED\nUse average quantity"]
        V5["Status: DISCREPANCY\nUse conservative quantity\nFlag for review"]
        V6["Status: PRIMARY_ONLY\nor SECONDARY_ONLY"]
        V7["Output: Consensus BOQ\n+ verification summary"]
        V1 --> V2 --> V3
        V3 -->|Yes| V4
        V3 -->|No| V5
        V2 -->|Unmatched| V6
        V4 --> V7
        V5 --> V7
        V6 --> V7
    end

    E3 --> A2
    E3 --> A3
    A2 --> A4
    A3 --> A4
```

### Verification Status Matrix

| Status | Meaning | Action Required | UI Color |
|--------|---------|----------------|----------|
| `agreed` | Both agents within ±15% | None — high confidence | Green |
| `discrepancy` | Agents differ >15% | Human review recommended | Amber |
| `primary_only` | Only primary agent found item | Verify scope inclusion | Blue |
| `secondary_only` | Only secondary agent found item | Verify scope inclusion | Purple |
| `unverified` | Single-agent run | Manual QA advised | Grey |

## 7. Cost Optimization Playbook

### Strategy 1 — Caching & Deduplication

```mermaid
flowchart LR
    REQ["BOQ Request"] --> HASH["SHA-256 hash\nof document content"]
    HASH --> CACHE{"Cache\nhit?"}
    CACHE -->|Yes, < 24hrs| RETURN["Return cached BOQ\nCost: $0"]
    CACHE -->|No| AI["Run AI Pipeline"]
    AI --> STORE["Store result\nwith TTL"]
    STORE --> RETURN2["Return fresh BOQ"]
```

**Estimated savings: 40–60%** for projects with repeated document sets (common in infrastructure projects).

### Strategy 2 — Intelligent Chunking

Instead of sending full documents to all 4 agents, only Agent 1 (Extractor) receives raw text. Agents 2–4 receive the structured extraction summary (~80% smaller).

```
Full Document:     ~15,000 tokens × 4 agents = 60,000 tokens
Optimized:         ~15,000 tokens (Agent 1) + ~3,000 × 3 agents = 24,000 tokens
Token Savings:     60%
```

### Strategy 3 — Local Ollama for Extraction

Use a local Ollama model for Agent 1 (Document Extractor) — the cheapest and simplest task. Only send the structured output to cloud models for higher-level reasoning.

```mermaid
graph LR
    DOC["Document\n15,000 tokens"] --> OLL["Ollama Local\nLlama 3.2\nAgent 1\nCost: $0"]
    OLL --> EXTRACT["Structured\nExtraction\n~2,000 tokens"]
    EXTRACT --> CLOUD["Cloud Model\nAgents 2-4\nCost: minimal"]
```

**Estimated savings: 30–50%** on token costs.

### Strategy 4 — Async Queue Processing

```mermaid
graph TD
    API["API receives\nBOQ request"] --> QUEUE["Add to\nBullMQ Queue\n(priority: standard)"]
    QUEUE --> RETURN_ID["Return job_id\nimmediately\n(HTTP 202)"]
    QUEUE --> WORKER["Worker pulls\nfrom queue"]
    WORKER --> AI_PROC["Run AI Pipeline\n(off peak hours\nfor lower API costs)"]
    AI_PROC --> NOTIFY["Notify user\nvia webhook/email"]

    URGENT["Urgent BOQ\nrequest"] --> PQUEUE["Priority Queue\n(premium tier)"]
    PQUEUE --> FAST_WORKER["Fast Worker\n(immediate)"]
```

**Benefit:** Process jobs during off-peak API hours for lower costs, avoid rate limits at scale.

### Strategy 5 — Model Fallback Chain

```mermaid
graph LR
    TRY1["Try: Primary Model\ne.g. GPT-4.1"] -->|Rate limit or error| TRY2["Try: Fallback 1\ne.g. Claude 3.5 Haiku"]
    TRY2 -->|Error| TRY3["Try: Fallback 2\ne.g. Llama 3.3 70B (OpenRouter)"]
    TRY3 -->|Error| TRY4["Try: Fallback 3\ne.g. Local Ollama"]
    TRY4 -->|Error| ERR["Return error\nwith partial results"]
```

## Key Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **API Framework** | Express 5 | Mature, async-native, excellent middleware ecosystem |
| **ORM** | Drizzle + PostgreSQL | Type-safe, lightweight, excellent migrations |
| **AI Abstraction** | OpenAI-compatible API | Works with OpenAI, Ollama, OpenRouter with same codebase |
| **Streaming** | SSE (Server-Sent Events) | Simpler than WebSocket for unidirectional AI output streaming |
| **Multi-Agent Pattern** | Sequential + Parallel | Agent 1 sequential → Agents 2+3 parallel → Agent 4 sequential |
| **Verification** | LLM-based comparison | More accurate than rule-based (handles paraphrased descriptions) |
| **Cost Control** | Provider abstraction | Switch models per tier without code changes |
| **Local Models** | Ollama integration | Zero cost option for dev/testing, air-gap compliance |

kubectl apply -f k8s/

# TenderLogix — Enterprise Platform Roadmap
## AI-Powered Tender-to-Award Workflow for Construction

> **Version:** 2.0 | **Audience:** Enterprise Architects, CTOs, Bid Directors | **Market:** Middle East & International Construction

---

## 1. Platform Overview

TenderLogix transforms the fragmented construction tendering process — currently spread across Excel, AutoCAD, Word, and email — into a **single controlled workspace** with AI assistance at every stage.

### The Problem (Current State)
```
RFP arrives → Email → Excel (BOQ) → AutoCAD → Word → PDF → Email → Repeat
     ↓              ↓           ↓           ↓
No version control  Errors  No audit trail  Manual sync
```

### The Solution (TenderLogix)
```
RFP arrives → TenderLogix → AI Analysis → Structured Workspace → One-click Export
     ↓                ↓              ↓                 ↓
Full audit trail   RAG-enhanced   Multi-agent BOQ   PDF/Excel output
```

## 14. Key Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Vector DB** | pgvector | Eliminates Pinecone/Weaviate cost; single DB handles relational + vector |
| **Embeddings** | sentence-transformers | Open source, zero cost, runs locally, 90% quality vs OpenAI |
| **Multi-agent** | Parallel domain specialists | Higher accuracy than one generalist; agents stay focused |
| **Deduplication** | Programmatic (word overlap) | Reliable at scale; LLM can't regenerate 300+ items reliably |
| **Streaming** | SSE (Server-Sent Events) | Simpler than WebSocket for unidirectional AI output |
| **AI Gateway** | LiteLLM proxy | Switch providers without code changes; centralized cost control |
| **Local models** | Ollama integration | Zero cost for dev/testing; air-gap compliance for sensitive tenders |
| **Queue** | BullMQ + Redis | Reliable async processing; retry logic; BOQ generation is long-running |
